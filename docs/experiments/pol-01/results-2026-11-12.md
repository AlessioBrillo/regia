## Setup (recorded, not assumed)

| Item | Value |
|---|---|
| Engines | `cedar-policy` 4.14.1 (strict schema validation); `regorus` 0.15.0 (Rust, OPA-compatible interpreter, **not OPA**) |
| Toolchain | `rust:1.98.1` container (the CI image) |
| Host | Intel Core 7 150U, 12 threads, Windows 11 running the container under WSL2 (kernel 6.18.33.2) |
| Policy sources | `regia.cedar` 56 lines + `regia.cedarschema` 26 lines; `regia.rego` 110 lines |
| Input | Synthetic identities only; no personal data |

Local test binaries cannot run natively on the owner's Windows 11 (an Application Control policy blocks unsigned
build outputs, os error 4551); all runs are in the container, which is also what the gate does. This is a finding for
CL-01 and for any on-device build plan, not a policy result.

## Gate

| Check | Cedar | Rego | Note |
|---|---|---|---|
| P-01..P-09, P-11 case table (all rows, incl. reason and policy version present) | pass | pass | 12 tests |
| P-06 every error path denies (missing/unknown/empty label, no membership, malformed policy → no engine, schema-invalid policy → no engine) | pass | pass | no path maps to `allow` |
| P-10 disagreements with the oracle, 10 000 random triples over a 5-circle tree | **0** | **0** | proptest |
| No case lets model output decide or override | n/a | n/a | engine input has no model-derived authority; only `origin`/`approved` |

The property test is sensitive: mutating the oracle's ancestor-owner rule (view-only → any action) made it fail
immediately with a shrunk counterexample, and the mutation was reverted.

## Failed cases, limits, anomalies

- First attempt of the property test took 176 s because the engine was rebuilt per case; fixed (thread-local), 15 s.
- `regorus` is not OPA. A Go OPA sidecar, OPA's own tooling (`opa test`, `opa check --strict`, `opa fmt`) and the
  bundle/rollout story were **not** evaluated. If OPA proper is the real alternative, this card under-tests it.
- The oracle, Cedar and Rego rules were written by the same author in one sitting; agreement shows the engines
  implement the written rules identically, not that the rules are the right ones. Rule review is a separate step.
- Roles/labels are still the provisional `regia-domain` names; nothing here fixes the taxonomy.
- Not covered: policy rollout/rollback, mid-workflow version change (only the version stamp), on-device latency,
  AR-14 across real surfaces (search, sync, notifications), the 5 000+ resource workloads of DAT-01.

data does not have.

## Outcome

**Trial Cedar** for the policy engine; keep the oracle as a permanent differential-test fixture whatever the final
choice. Not an adoption: iOS/Android bindings (CL-01), OPA proper, and rule review remain open. Proposed in
[ADR-005](../../adr/005-policy-engine.md); acceptance is the owner's decision.

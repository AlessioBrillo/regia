## Conflict rules fixed by the owner for this spike (2026-11-12)

Fixed so that every alternative is judged against the same behaviour. They are **spike constraints**, not ratified
semantics: they become decisions only through ADR-003 accepted with evidence.

- **S-03, same field edited concurrently:** the write with the greatest hybrid logical clock wins (ties broken by device
  id). Every other concurrent value stays visible as a conflict until someone writes the field again; writing the lost
  value back restores it. No silent loss.
- **S-05, delete vs an edit the delete had not seen:** the edit resurrects the object and the deleter gets a notice.
  An edit made after seeing the delete is refused, as the object is deleted until restored (S-04).

Harness: [`spikes/dat01`](../../spikes/dat01). Increment 1 runs both alternatives through one trait and one
deterministic simulator, over the synthetic dataset, with a differential property test (same history on A and B must
give the same visible state) and the canary scan after every workload.

## Questions the spike must answer (report §4.3)

1. What is the single source of truth for each object: a CRDT document, a SQL table or a domain event?
2. How is the local index kept consistent with the source, and rebuilt after corruption or migration?
3. How is it prevented that an index, notification, cache or search result reveals unauthorised metadata?
4. How do merge and delete behave when a member has been removed or no longer holds the keys?

## Dataset (synthetic, reproducible)

Generated by `core/domain/examples/dat01.rs`, a pure function of `(seed, profile)`. Every line is a schema-v0
`Envelope`, built through the same validation as the contract suite in `core/domain/tests`. No personal data.

```text
cargo run -p regia-domain --example dat01 -- <seed> <small|large> > dataset.jsonl
```

| Profile | Circles | Principals | Persons | Sources | Tasks+events+documents | Lines (seed 42 / 1) |
|---|---:|---:|---:|---:|---:|---:|
| small | 6 | 4 | 7 | 12 | 36 | 76 / — |
| large | 40 | 50 | 90 | 400 | 6000 | — / 6652 |

Properties (asserted by the example's tests, which run in the CI gate):

- Same seed gives identical bytes; different seeds differ.
- Circles nest to depth ≥ 3; every label, server visibility, source kind and date role appears.
- Every reference resolves **and stays inside its circle** (parent circle, membership, source refs, assignees,
  participants).
- `restricted` and `secret` objects are never `server_readable`.
- **Canaries:** exactly the `restricted`/`secret` titles contain `CANARY-<circle>-<n>`. A canary found in an index,
  log, cache, notification, snippet, prompt or export visible to a principal who may not read that object is a
  **security failure** (AR-04), regardless of any performance result.

Seeds: `1..=10` for the repetitions; `42` is the reference seed for documentation.

## Scenarios

Each scenario runs for every alternative, with 2 and with 5 clients unless stated, with offline periods injected.

| ID | Scenario | Intent that must survive |
|---|---|---|
| S-01 | Offline writes on every client, then reconnect | All writes present or explicit conflict |
| S-02 | Same object edited concurrently on two clients (different fields) | Both edits |
| S-03 | Same field edited concurrently | Explicit, deterministic outcome; no silent loss |
| S-04 | Delete, then restore | Restored state equals pre-delete state |
| S-05 | Delete on one client vs edit on another | Declared rule; user informed |
| S-06 | Schema migration v0→v1 while clients are mid-sync | No object lost or unreadable |
| S-07 | Crash during a write (process kill, power-loss simulation) | Store consistent on restart, no torn object |
| S-08 | Return online after a long offline backlog | Convergence time and bytes bounded |
| S-09 | Member removed while a device is offline; device returns with edits | Edits rejected/quarantined per the ADR; no access to later data |
| S-10 | Object moved to another circle | No residue in the old circle's index/cache |
| S-11 | Rebuild all indexes from the source of truth | Identical results before and after |
| S-12 | Simultaneous access from several local processes | No corruption, no lost update |

## Gate and scoring

1. **Gate first (pass/fail, not averaged):** zero isolation failures (no canary leak); 100% of tested scenarios
   converge or surface an explicit conflict with no silent loss (report §8.3); crash scenarios end consistent; export
   round-trips. An alternative that fails any gate is rejected regardless of score.
2. Only survivors are scored with the **frozen weights** in [`TEMPLATE.md`](TEMPLATE.md). Weights change only before
   results are seen.
3. A synthetic performance benchmark alone never selects an alternative (report §4.3 gate).

## Sensitivity (the checks can fail)

Each mutation was applied to the source, the tests run, and the source restored (`git checkout`).

| Mutation | Result |
|---|---|
| Tie-break inverted (`pick` sorts the stamps ascending) | Caught: the unit test and S-03 (both tests) fail on A and B (1 unit test + 4 scenarios) |
| Relay ignores circle scope (`intersection` → `union` of two devices' circles) | Caught on A: 7 scenarios fail (a device is asked to sync a circle it does not hold). **B was not affected**: it refuses ops of circles it does not hold, so its own check masks the broken relay. The canary scan is therefore tested only through that refusal, not through an actual leak; a leak-injecting mutation is increment 2 |

## Findings that matter for the ADRs

1. **A native delete loses concurrent edits.** In Automerge, deleting the object key makes a concurrent edit to its
   fields vanish silently. A needed an explicit tombstone register plus the heads the deleter had seen, and per-commit
   messages to attribute unseen changes to objects. This is application logic on top of the CRDT, as report §4.4
   warns. B needed the equivalent in a version vector per op.
2. **Concurrent creation of the same object id** produces two Automerge map objects; one wins arbitrarily. The
   differential test only avoids it because ids are UUIDs and one device creates each id. Not tested beyond that.
3. **A document per circle** gave isolation for free (a device never loads a circle it is not in). B enforces it in
   the sync scope and refuses ops of circles it does not hold.
4. **Restoring from an older snapshot needs a fresh Automerge actor id**, or operation ids are reissued. B has no
   such hazard (sequence numbers come from the database).

## Failed cases, limits, anomalies

- **S-07 is weak.** B's crash is an aborted transaction (rollback), not a killed process or power cut; A's is a
  truncated save, not a torn write on disk. SQLite's journal and Automerge's loader are trusted, not re-tested.
- Clocks: one global simulated clock, so stamp order always agrees with causal order. Skew is not tested, and neither alternative merges a received stamp into its own clock (so the "hybrid" clock is a plain wall clock) nor persists it across a restart. A device with a slow clock can lose a last-writer-wins race against older intent.
- Concurrent creation of the same object id diverges: Automerge keeps one map object and drops the other's fields silently, B merges them. The differential test avoids it (one creator per id); UUID ids make it unlikely, not impossible.
- B refuses an incoming log with a gap per author and an op that would collide; A relies on Automerge's own integrity checks.
- Isolation is now also tested at the replica: genuine messages of a circle are delivered straight to a replica that does not hold it, and both refuse them. Before this, the canary scan passed by construction, because the simulator never connects non-members.
- The index is an in-memory map for both alternatives (the projection store is not part of this comparison).
- Membership is static. Revocation while offline (S-09), moves between circles (S-10), migration (S-06) and
  multi-process access (S-12) are not covered.
- Encryption (CRY-01) and policy (POL-01) are out of scope; the data is plaintext fixtures.
- Differential test: 96 random histories per run, 3 devices, one circle, 4 objects. Not exhaustive.
- Large, 2 devices: see above.

## Outcome

**No recommendation yet.** Neither alternative is rejected. The increment shows both can meet the owner's rules for
conflicts, deletes and isolation, at a cost: the CRDT does not give the delete rule for free. The decision needs
increment 2 (revocation while offline S-09, migration S-06, backlog S-08, alternative C, a stronger S-07, clock skew)
and CL-01 (can the chosen library run on iOS, Android and Windows). ADR-002 and ADR-003 stay `proposed`.
